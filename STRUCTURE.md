```text

├── index.html              # Single shell entry point (no monolithic page files)
├── css/style.css           # All styles in one module
├── js/
│   ├── init.js             # Main entry point — wires imports, boots DOMContentLoaded
│   ├── stores/state.js     # Centralized app state, payload builder, metrics, tab switching
│   ├── data/schema.js      # SCHEMA_VERSION, isValidPayload, EMPTY_PAYLOAD
│   ├── data/migrations.js  # Schema migration functions (v3→v4)
│   ├── data/store.js       # collectSectionPayload, buildDemoStarterPayload
│   ├── actions/data.js     # refreshFromShare, saveToInbox, importJsonPayload
│   ├── actions/editor.js   # addIdea, addQuestion, addAction, deleteIdea, etc.
│   ├── utils/strings.js    # escapeHtml, normalizeText

│   ├── utils/ui.js         # showToast, toggleMoreActions

│   ├── Cargo.toml
│   ├── tauri.conf.json
│   ├── src/                # commands.rs, lib.rs, main.rs, paths.rs
│   ├── capabilities/
│   ├── permissions/

```

## Design decisions

### No monolithic files
- `index.html` is the single HTML shell — no separate page HTML files
- `css/style.css` contains all styles in one module — no per-component CSS files
- `js/init.js` is the sole entry point — all other modules are imported, not standalone
- `js/stores/state.js` centralizes all app state and tab switching — no scattered globals

### Modular JavaScript (ES modules)
- All JS uses `import`/`export` — no script-tag concatenation
- `stores/` — state management and payload building
- `data/` — schema validation and migrations
- `actions/` — side effects (share I/O, editor operations)
- `utils/` — pure helper functions
- `components/` — reusable UI components (initiatives, notes, sections)
- `pages/` — page-level render functions (dashboard, problems, analytics)

### Tauri build pipeline
1. `scripts/prepare-frontend.js` copies root `index.html`, `css/`, `js/` → `www/`
2. Tauri reads from `www/` as its web source
3. `src-tauri/` Rust code handles file I/O, shared folder access, and operator identity
4. No custom bundler — copy-only stage keeps the build simple

### State management
- `state.js` holds `currentPayload`, `currentTab`, `currentInitiativeId`
- `switchTab()` toggles `.page` visibility and calls `renderCurrentTab()`
- `buildSharePayload()` constructs the JSON payload for share operations
- `updateProgress()` and `updateMetrics()` recalculate from the DOM

### No framework
- Vanilla JavaScript with ES modules
- No React, Vue, Svelte, or bundler
- DOM manipulation via `document.querySelector` and `innerHTML`
- CSS custom properties (`--primary`, `--accent`, etc.) for theming
